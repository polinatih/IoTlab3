# IoT — Лабораторные 3.1 и 3.2: аналоговый датчик температуры TMP36 + LCD 1602 + FreeRTOS

Одна программа на обе лабы (структура как в видео преподавателя): `main.cpp` передаёт
управление приложению, выбранному в `src/app_config.h`.

```c
#define APP_NAME  APP_LAB_3_1   // 3.1 — снятие сигнала
#define APP_NAME  APP_LAB_3_2   // 3.2 — кондиционирование сигнала (по умолчанию)
```

## Схема подключения (Arduino Uno) — как в Tinkercad

| Компонент | Вывод | Arduino |
|---|---|---|
| TMP36 (плоской стороной к себе) | левый — +Vs | 5V (шина «+») |
| | средний — **Vout** | **A0** |
| | правый — GND | GND (шина «−») |
| LCD 1602 I2C | GND / VCC | GND / 5V |
| | SDA / SCL | A4 / A5 |
| Зелёный LED (NORMAL) | анод через 220 Ом | D6 |
| Красный LED (WARNING) | анод через 220 Ом | D7 |
| Катоды обоих LED | | GND |
| Heartbeat | встроенный светодиод «L» | D13 (без проводов) |

## Arduino Mega 2560 (лаборатория)

Плата выбирается в `platformio.ini` строкой `default_envs` (`mega` или `uno`). Сейчас стоит **mega**.
Для Wokwi (там Uno) поставьте `default_envs = uno` и нажмите Build.

TMP36 (A0) и светодиоды (D6, D7) подключаются к Mega так же, как к Uno. Разница — только LCD.
Программа на Mega **сама определяет**, какой экран подключён, и пишет в Serial `LCD: ...`.

**LCD с платой I2C сзади (4 провода):** GND → GND, VCC → 5V, **SDA → 20**, **SCL → 21**
(на Mega I2C — это пины 20/21, а не A4/A5).

**Параллельный LCD 1602A (16 выводов):**

| № | Вывод LCD | Mega |
|---|---|---|
| 1 | VSS | GND |
| 2 | VDD | 5V |
| 3 | V0 (контраст) | средняя ножка потенциометра 10 кОм (крайние — 5V и GND) |
| 4 | RS | 12 |
| 5 | RW | GND |
| 6 | E | 11 |
| 7–10 | D0–D3 | не подключать |
| 11 | D4 | 5 |
| 12 | D5 | 4 |
| 13 | D6 | 3 |
| 14 | D7 | 2 |
| 15 | A (подсветка +) | 5V через 220 Ом |
| 16 | K (подсветка −) | GND |

Пины параллельного экрана меняются в `src/srv/srv_lcd_stdio/srv_lcd_stdio.h` (`SRV_LCD_PIN_*`).

## Задачи FreeRTOS

| Задача | Период | Смещение | Приоритет | Что делает |
|---|---|---|---|---|
| Heartbeat | 500 мс | 0 | 1 | мигает LED D13 |
| TempSensor | 50 мс | 20 мс | 2 | съём + кондиционирование сигнала |
| TempAlert | 100 мс | 40 мс | 2 | NORMAL / WARNING, светодиоды |
| Report | 500 мс | 100 мс | 1 | отчёт `printf` в Serial и `fprintf` на LCD (и команды в 3.2) |

Период — `vTaskDelayUntil()`, смещение — `vTaskDelay()` в начале задачи.
Тик FreeRTOS на Uno ≈ 16 мс, поэтому реальные времена кратны 16 мс (500 мс → 496 мс).

## Поток сигналов (драйвер `dd_sns_temperature`)

| № | Сигнал | Как получается |
|---|---|---|
| 1 | `raw` | `analogRead(A0)`, 0..1023 |
| 2 | `voltage_mv` | `map(raw, 0, 1023, 0, 5000)` + смещение калибровки |
| 3 | `saturated_mv` | насыщение 100..1750 мВ (рабочий диапазон TMP36: −40..+125 °C) |
| 4 | `median_mv` | «соль и перец»: FIFO 5 → копия → `qsort` → элемент [5/2] |
| 5 | `filtered_mv` | взвешенное среднее: 50 % · новый + 25 % + 15 % + 10 % · старые |
| 6 | `temperature_deci` | TMP36: T = (U − 500 мВ) / 10 мВ/°C → в 0.1 °C, насыщение −40..+125 °C |

В лабе 3.1 используется только 1 → 2 → температура (без фильтров).
Всё в целых числах: у ATmega328P нет аппаратной плавающей точки.

## Дополнительное поведение

T ≥ 30.0 °C → **WARNING**: горит красный LED, на LCD «WARNING», в Serial предупреждение.
Назад в **NORMAL** (зелёный LED) — только когда T < 29.0 °C (гистерезис 1 °C).
Чтобы проверить на настоящем датчике — зажмите TMP36 пальцами.

## Запуск

1. VS Code + PlatformIO → File → Open Folder → эта папка.
2. В `src/app_config.h` выбрать лабу (`APP_LAB_3_1` или `APP_LAB_3_2`).
3. Подключить Uno → **Upload** (стрелка внизу) → **Serial Monitor** (вилка), 115200.

Пример отчёта 3.1:
```
[    4.0 s] #0085 | raw= 166 | U= 811 mV | T= 31.1 C | state=WARNING
            !!! WARNING: overheating (on at >= 30 C, off below 29 C)
```
LCD:
```
T= 31.1C WARNING
ADC 166   811mV
```

Пример отчёта 3.2 (с тестовыми помехами — команда `n` в Serial Monitor):
```
[    9.5 s] raw=   0 | mV=   0 | sat= 100 | med= 791 | flt= 792 | T= 29.2 C | WARNING | SAT | NOISE
[   12.0 s] raw=1023 | mV=5000 | sat=1750 | med= 796 | flt= 787 | T= 28.7 C | NORMAL | SAT | NOISE
```
Импульсы `raw=0` и `raw=1023` срезало насыщение (`sat`) и полностью убрала медиана (`med`).
LCD в 3.2: `U` — напряжение до фильтров, `F` — после, `*` — помехи включены.

## Проверка в VS Code без платы (симулятор Wokwi)

В проекте есть `diagram.json` и `wokwi.toml` для расширения **Wokwi Simulator** в VS Code.
1. Установить расширение «Wokwi Simulator», затем F1 → «Wokwi: Request a New License» (бесплатно).
2. PlatformIO: **Build** (галочка внизу).
3. F1 → **Wokwi: Start Simulator**.

В Wokwi нет детали TMP36, поэтому на A0 стоит **потенциометр** — программа считает его
напряжение как выход TMP36. Ручка почти в нуле: 15 % хода ≈ 0.75 В ≈ 25 °C; чуть дальше
16 % ≈ 0.80 В ≈ 30 °C → WARNING. На настоящей плате вместо него — TMP36.

## Команды Serial Monitor (лаба 3.2)

- `n` — включить / выключить тестовые помехи (импульсы «соль/перец» 0/1023 и шум ±2)
- `h` — подсказка

## Если что-то не так

- Температура около −40 °C или 125 °C — перепутаны выводы TMP36 (Vout должен идти на A0).
- LCD светится, но пустой (или горят чёрные квадраты в верхней строке) — подкрутить контраст:
  синий винт на плате I2C, у параллельного экрана — потенциометр на выводе V0.
- На Uno I2C-экран не отвечает — поменять `SRV_LCD_I2C_ADDRESS` на `0x3F` в `srv_lcd_stdio.h`
  (на Mega оба адреса проверяются автоматически).
- В лаборатории другой аналоговый датчик (LM35, KY-013) — меняется только функция
  `dd_sns_temperature_mv_to_deci()` и границы насыщения в `dd_sns_temperature.h`.
- Heartbeat (LED «L») не мигает, отчёта нет — программа зависла при старте. Посмотрите строку
  `Free heap before scheduler start`: FreeRTOS нужно ~480 байт на служебные задачи.
  Если памяти мало — уменьшить `*_STACK` задач или буферы Serial в `platformio.ini`.
- Строка `[diag] free stack` показывает свободный стек задач; если число близко к 0 — увеличить `*_STACK`.
